Jelly / Developer documentation

What can Jelly do?

Jelly gives your AI assistant tools to read pages, click and type, check results, capture evidence, and ask for help. This guide shows which tool to use, then provides the exact inputs and outputs for developers.

What is a tool surface? It is the set of tool names Jelly shows to a connected AI assistant. The default small surface groups browser actions behind three tools: browser-schema, browser-call, and browser-events. The large surface exposes individual actions such as click and read-page as separate tools. Both use the same Jelly browser engine; this choice changes how the AI calls tools, not where Chromium runs. Compare the surfaces below.

Start here: three basic browser tools

An MCP tool is an action an AI assistant can request from Jelly. You do not have to write JSON to use one through a connected AI client. For ordinary browser work, these three tools cover discovery, actions, and live events.

01 / DISCOVER

Find out what Jelly can do

browser-schema shows browser operations such as reading a page, finding a button, or checking a result. It does not change the page.

02 / ACT AND CHECK

Use the browser

browser-call carries out browser operations: read content, click, type, and explicitly verify what happened.

03 / OBSERVE (OPTIONAL)

Follow browser activity

browser-events lets an agent subscribe to and inspect retained browser events when a task needs them.

New to Jelly? Follow Getting Started to install and connect it. When ready, try the first working MCP example, or copy the startup prompt to confirm tool discovery from your AI chat. A successful browser action alone does not prove the requested outcome; use a verification operation when the result matters.

For developers: authentication and responses

Jelly currently publishes 16 tools through the default MCP configuration. A running Jelly server tells each AI client which tools and parameters are available.

Show MCP schemas, authentication, and response formats

The checked-in [mcp].surface = "small-surface" publishes the three browser tools below plus thirteen system tools. Each has an authentication requirement: a valid static bearer token or OAuth access token with the jelly scope. The envelope for each successful call is result.structuredContent = {ok:true,data:…,error:null,meta:{tool:"…"}}; failures include ok:false, a typed error.kind, human-readable message, and retryable. The data field may be parsed CLI text or a structured value depending on the binding; example data below is schematic, not recorded execution output.

Source of truth: the running server's tools/list schema. Browser semantic operations are discovered with browser-schema and executed with browser-call. The large-surface alternative instead publishes individual browser primitives; see the generated internal capability index, but confirm remote publication through tools/list.

Advanced: multiple browsers and remote downloads

Show browser IDs, remote storage, and security details

When the remote CDP backend is configured, tools/list adds optional top-level browser_id to tool inputs. Select the immutable UUID or an easy name such as Jelly-Applepie. This chooses a Chromium instance; target still chooses a page inside that browser. The native backend omits this field. Remote download policies are remote-only, shared-volume and transfer. Explicit download action: "transfer" uses a separately configured HTTP(S) file bridge; HTTP transfers are unencrypted and warned about. Browser connection and sandbox security choices are independent of the MCP client authentication policy.

Choosing a tool surface

A surface is the list of MCP tools visible to your AI client. The small surface (the default) offers three general browser tools plus 13 system tools. The large surface offers individual browser operations, such as click and read-page, plus the same system tools. You do not need to switch surfaces to choose native Chromium, Docker/Podman, or remote CDP.

Query tools/list on the running MCP server for the active catalog and input schemas. See the MCP reference for deployment settings and advanced configuration.

Expanded large-surface API

When [mcp].surface = "large-surface", the three browser façade tools are replaced by 47 individual browser primitives described below. All 13 system tools above remain published. Since the current raw CDP configuration, this alternate mode additionally exposes cdp-call, totaling 61 tools. Confirm the active set using the runtime tools/list.

Shared permissions: bearer token or OAuth jelly scope. Shared result: structuredContent containing ok, data, error, meta.tool. Common errors: invalid_arguments, browser_unavailable, plus typed target/condition/script failures as appropriate. cdp-call | privileged raw protocol

Parameters
calls: required array, 1–64 items. Each item requires scope: "target" | "browser" and call: {method: "Domain.command", params?: object}; target scope optionally accepts a logical target. on_error: "stop" | "continue" defaults to stop.
Permissions
Bearer/OAuth jelly scope; raw CDP enabled by operator.
Side effects
Privileged browser/page observation or mutation; bypasses semantic policy.
Errors
invalid_arguments, browser_unavailable, cdp_failed.
Output
Same MCP envelope with per-call outcomes; protocol success is not proof of a workflow goal.
Example cdp-call arguments 
{"calls":[{"scope":"browser","call":{"method":"Target.getTargets","params":{}}}]}
