Browser deployment

One Jelly. Three ways to run Chromium.

Match your browser environment to the job: run Chromium directly on Linux, use a dedicated Docker/Podman container, or connect to a browser you already manage elsewhere.

NATIVE CHROMIUM

Start on your machine.

Use Chromium installed on the Jelly host for a straightforward local browser setup, without requiring a container engine.

DOCKER / PODMAN

Choose container isolation controls.

Deploy Chromium on a dedicated bridge network with isolated, shared, or ephemeral profiles. Choose Chromium sandbox and container restrictions independently; CDP ports are not published by default.

EXTERNAL CDP

Connect an existing browser.

Attach to a separately managed Chromium endpoint over CDP and address individual browsers by UUID or Jelly alias, without handing Jelly control of the external browser lifecycle.

Security is configurable, not assumed. A reachable container does not prove Chromium's sandbox is active. Public CDP exposure requires operator-managed network protections.

MCP working example

Discover tools without starting Chromium.

With a running server and a valid local bearer token, call the stateless browser-schema tool using the standard MCP tools/call method. 

curl http://127.0.0.1:8787/mcp \
  -H "Authorization: Bearer $JELLY_MCP_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"browser-schema","arguments":{"action":"capabilities"}}}'

A successful JSON-RPC response includes result.structuredContent.ok: true and result.structuredContent.data.action: "capabilities", with categories and an operation count. Permission: bearer token or OAuth jelly scope. Limitation: this verifies MCP discovery, not browser readiness.

Quickstart

Try Jelly.

Check your Linux prerequisites, preview MCP settings, then run the real quickstart. Select a browser runtime, configure authentication and hosting, and confirm service installation.

jelly / quickstart 
$ git clone https://github.com/FabioFlorey/jelly.git
$ cd jelly
$ ./scripts/dev.sh doctor

# preview setup without changing services or secrets
$ ./scripts/dev.sh setup --dry-run

# configure browser, MCP, and start Jelly after review
$ ./scripts/dev.sh

For hosting, credentials, and the first MCP request, follow the step-by-step installation guide.
