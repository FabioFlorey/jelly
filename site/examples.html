Jelly MCP Request Examples

Two tool-call recipes based on Jelly's current Rust schemas, with setup, expected result shapes, and limitations.

Example 1: Discover browser operations

Objective: Confirm authenticated MCP access and list semantic capability categories. Setup: Start Jelly and load JELLY_MCP_TOKEN from the local .env file. No Chromium process is needed for this stateless tool. 

source ./scripts/config.sh
jelly_load_env
curl --fail --silent --show-error http://127.0.0.1:8787/mcp \
  -H "Authorization: Bearer $JELLY_MCP_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"browser-schema","arguments":{"action":"capabilities"}}}'

Example 2: Read a page through MCP

Objective: Read content from a running Chromium page. Setup: After the server and token are configured, start the browser using the system MCP tool: 

curl --fail --silent --show-error http://127.0.0.1:8787/mcp \
  -H "Authorization: Bearer $JELLY_MCP_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"open-browser","arguments":{"url":"https://example.com"}}}'

Then call browser-call with a single ordered semantic operation: 

curl --fail --silent --show-error http://127.0.0.1:8787/mcp \
  -H "Authorization: Bearer $JELLY_MCP_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"browser-call","arguments":{"calls":[{"call":{"jelly":"read-page","params":{}}}]}}}'

Expected result: A JSON-RPC result containing structuredContent.ok: true and per-call data if Chromium opened and the page was read. The exact page text and JSON payload depend on Chromium and the network. Do not treat this as an end-to-end test result from a clean environment; the request and argument shapes are derived from the current Rust schemas.

Close the browser when finished by calling close-browser with empty arguments. A failed browser launch returns a structured error (such as browser_unavailable).

Limitations: Real sites may require authentication, and actions can have side effects. Do not submit purchases or change accounts without consent. Reference: Tool parameters and Tool reference.
