Install and Configure Jelly

Install Jelly, choose your MCP connection, and make your first tool call.

1. Prerequisites

Platform: Linux with a working systemd --user manager. Runtime: Rust 1.98.1 and Cargo, Chromium at /usr/bin/chromium, Bash, Git and common core utilities. curl is used for the checks below. Remote Quick Tunnel mode additionally needs cloudflared; nip-io needs Caddy and a reachable public IPv4 address.

2. Get the checkout and audit prerequisites 

git clone https://github.com/FabioFlorey/jelly.git
cd jelly
./quickstart.sh --check
./quickstart.sh --dry-run

The first command checks dependencies. The dry run previews configuration without saving .env, building binaries or starting services. Fix reported failures before proceeding.

3. Choose the client and hosting profile

Remote ChatGPT: The checked-in config/jelly.toml contains the chatgpt / remote-http / oauth profile. Choose quick-tunnel, cloudflare-fixed or nip-io in the wizard. The hosting wrapper must provide an actual public HTTPS JELLY_PUBLIC_URL. An arbitrary fake URL is not a working proxy.

Local generic MCP client: Remove the [[mcp.connections]] entry whose provider is chatgpt from config/jelly.toml when using local-only hosting without HTTPS. Keep the generic-mcp / local-http / bearer-token profile. Otherwise the remote profile fails startup validation.

See connection options for a walkthrough of each client setup.

4. Set credentials and start services 

./quickstart.sh

Answer the hosting and authentication prompts. Select installation/startup of the user services. The wizard writes local secrets to the ignored .env file with restricted permissions and installs the configured services. Do not commit or share that file.

For local HTTP clients, use the configured JELLY_MCP_TOKEN. For remote clients, complete the configured OAuth flow. The single OAuth scope is jelly.

5. Verify service and MCP tool call 

scripts/status-mcp-services.sh
curl --fail --silent --show-error http://127.0.0.1:8787/health
set -a
source ./.env
set +a
curl --fail --silent --show-error http://127.0.0.1:8787/mcp \
  -H "Authorization: Bearer $JELLY_MCP_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"browser-schema","arguments":{"action":"capabilities"}}}'

Expected: /health returns "status":"ok". The JSON-RPC response has a result.structuredContent object whose ok is true, meta.tool is "browser-schema", and data.action is "capabilities". Actual categories/counts depend on the current binary. This validates MCP discovery, not browser startup.

6. First browser operation and next steps 

cargo run --quiet --bin agent-run -- open-browser https://example.com
cargo run --quiet --bin agent-run -- read-page
cargo run --quiet --bin agent-run -- close-browser

These are local CLI browser operations, distinct from the MCP request above. A healthy MCP server alone does not imply an active browser. Next, read MCP request examples, the tool catalog, or failure diagnostics. The repository setup guide remains the authoritative detailed procedure.
